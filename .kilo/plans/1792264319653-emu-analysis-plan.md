# План: Анализ и исправление эмулятора DOS

## Сводный анализ

Проект состоит из 3 крейтов: `bus` (шина/материнская плата), `x86` (CPU+инструкции), `dos` (DOS-слой).
Архитектура в целом верная, но есть критические ошибки в реализации опкодов, флагов и пропущенные инструкции.

---

## 🔴 БЛОК 1: Критические баги (некорректное исполнение)

### 1.1 DIV r/m8 (opcode 0xF6 /6) — отсутствует проверка переполнения
**Файл:** `crate/x86/src/instructions/group.rs:48-56`
**Проблема:** Деление `AX / r/m8` вычисляет `AL = (AX / value) as u8` без проверки, что частное > 0xFF.
Если `AX / value >= 0x100`, реальный CPU генерирует INT 0 (Division Error). Эмулятор молча обрезает.
**Исправление:** Добавить проверку `if (ax / value as u16) > 0xFF { software_interrupt(cpu, machine, 0); return; }`

### 1.2 LOCK (0xF0) устанавливает `rep_type = Some(0xF0)`
**Файл:** `crate/x86/src/cpu.rs:171-174`
**Проблема:** 0xF0 — это LOCK, а не REP. Установка `rep_type` в Some(0xF0) может привести к ложному срабатыванию проверок `rep_type == Some(0xF2)` или `Some(0xF3)` в строковых операциях.
**Исправление:** Убрать `self.prefixes.rep_type = Some(0xF0)` из обработки 0xF0. LOCK не имеет rep_type.

### 1.3 MOVZX 0x0F 0xB7 — читает 8-битный источник при 16-битном операнде
**Файл:** `crate/x86/src/instructions/system.rs:378-397`
**Проблема:** `0x0F 0xB7` = MOVZX r16/32, r/m16. Источник ВСЕГДА 16-битный.
Код читает `read_reg8` / `read_mem_u8` когда `has_operand_size == false` (т.е. 16-битный режим).
Должен читать `read_reg16` / `read_mem_u16` ВСЕГДА, а регистр назначения — `write_reg16` или `write_reg32` в зависимости от префикса.
**Исправление:** Убрать ветвление по источнику. Всегда читать 16 бит.

### 1.4 0x0F 0x80-0x8F (near Jcc) — реализовано только 3 из 16
**Файл:** `crate/x86/src/executor.rs:368-388`
**Проблема:** Из 16 near-условных переходов (0x0F 0x80–0x8F) реализованы только:
- 0x82 → JB (0x72)
- 0x83 → JNB (0x73)  
- 0x84 → JE (0x74)
Остальные 13 отсутствуют (включая JO, JNO, JNE, JBE, JA, JS, JNS, JP, JNP, JL, JGE, JLE, JG).
**Исправление:** Добавить dispatch для 0x80–0x8F через `jcc_rel16` с соответствующими базовыми опкодами. Можно добавить маппинг: `opcode & 0x0F` как индекс в базовый массив `[0x70, 0x71, ..., 0x7F]`.

### 1.5 `jcc_rel16` — неверный базовый опкод для всех условий
**Файл:** `crate/x86/src/instructions/control.rs:44-54`
**Проблема:** Функция `cond(cpu, opcode)` использует `opcode & 0x0F` для выбора условия.
Для near Jcc (0x0F 0x80–0x8F) условие = `opcode & 0xF`. В current коде передается 0x72/0x73/0x74,
чьи нижние 4 бита = 0x02, 0x03, 0x04 — это верно для 0x82, 0x83, 0x84.
Для остальных (0x80, 0x81, 0x85–0x8F) эти условия неверны.
**Исправление:** Передавать в `jcc_rel16` оригинальный опкод (0x80–0x8F, нижние 4 бита = 0x00–0x0F).

### 1.6 ModRM resolve_32 — усечение до 16 бит вместо 20-битной адресации реального режима
**Файл:** `crate/x86/src/modrm.rs:122, 142, 178`
**Проблема:** `cpu.phys_addr(seg, effective as u16)` обрезает effective-адрес до 16 бит.
В real-mode с префиксом 0x67 (32-битная адресация) эффективный адрес может быть до 0xFFFF_FFFF,
но физический адрес (seg<<4 + offset) должен быть обрезан до 20 бит (0xFFFFF) при A20 off,
и до 0x10FFEF при A20 on. Усечение до 16 бит теряет биты 16-19.
**Исправление:** Убрать `as u16`. Передавать `effective` как `u32` в новую версию `phys_addr32` или маскировать по A20.

### 1.7 `lea` в 32-битном режиме — `resolve_offset` возвращает усечённый адрес
**Файл:** `crate/x86/src/modrm.rs:181-198`
**Проблема:** `resolve_offset` вызывает `resolve_32` и приводит результат к `u16`.
Для LEA в 32-битном режиме offset должен быть 32-битным.
**Исправление:** Для 32-битного режима и LEA, возвращать полный 32-битный effective адрес.

## 🟡 БЛОК 2: Отсутствующие, но важные опкоды

### 2.1 PUSH FS (0x0F 0xA0), PUSH GS (0x0F 0xA8), POP GS (0x0F 0xA9)
**Файл:** `crate/x86/src/executor.rs:368-388`
Требуются некоторыми DOS-программами (Watcom, DOS/4GW).

### 2.2 MOVZX r16/32, r/m8 (0x0F 0xB6)
**Файл:** `crate/x86/src/executor.rs`
Часто используется в 386 коде. Реализован только 0x0F 0xB7 (16→32).

### 2.3 MOVSX (0x0F 0xBE — 8→16/32, 0x0F 0xBF — 16→32)
Используется в компиляторах и играх.

### 2.4 SETcc (0x0F 0x90–0x9F)
Используется современными (для DOS) компиляторами.

### 2.5 CPUID (0x0F 0xA2)
Нужен многим программам для определения возможностей CPU. Должен возвращать корректные Vendor ID и Feature Flags (Gentoo Linux, многие игры).

### 2.6 RDTSC (0x0F 0x31)
Используется для профилирования.

### 2.7 SHLD (0x0F 0xA4/0xA5) и SHRD (0x0F 0xAC/0xAD)
Используются в оптимизированном коде.

### 2.8 BT (0x0F 0xA3), BTS (0x0F 0xAB), BTR (0x0F 0xB3), BTC (0x0F 0xBB), BT group (0x0F 0xBA)
Битовые инструкции, используются некоторыми DOS программами.

### 2.9 LMSW (0x0F 0x01 /6)
Запись младших 16 бит CR0. Нужен переключения в protected mode.

## 🟠 БЛОК 3: Дублирование кода и неконсистентность

### 3.1 INC/DEC — дублирование логики в `alu.rs` и `group.rs`
**Файлы:** `crate/x86/src/instructions/alu.rs:828-874`, `crate/x86/src/instructions/group.rs:291-312`
Обе реализации INC/DEC (для регистров и для r/m) делают одно и то же.
Объединить через общую функцию.

### 3.2 SCAS/CMPS — ручное вычисление флагов
**Файл:** `crate/x86/src/instructions/mov.rs:405-460, 538-589`
Вычисление флагов через `compute_flags_u*` напрямую. Лучше использовать `sub8/sub16/sub32` + `apply_arith*`.

### 3.3 Обработка прерываний — прямой доступ к SP в 3 местах
**Файлы:** `crate/x86/src/instructions/system.rs:28-50`, `crate/dos/src/system.rs:141-166`
И `software_interrupt`, и `raise_interrupt`, и `iret` вручную манипулируют стеком.
Объединить с `stack::push16/pop16`.

### 3.4 `apply_arith*`/`apply_logic*` используются не везде
Некоторые места (SCAS, CMPS) вызывают `set_flags` напрямую вместо `apply_arith*`.

## 🟢 БЛОК 4: Улучшения и технический долг

### 4.1 Переписать `rep_count` для правильного поведения REP-строк
Текущая реализация строковых операций с REP выполняет все итерации в цикле, что неправильно для прерываний. Для базовой работы сойдет, но отметим в TODO.

### 4.2 `0x0F 0x01 /0` и `/1` — SGDT/SIDT заглушки (записывают 0xFFFF, 0x00000000)
Реальная заглушка, но для DOS-совместимости — приемлемо.

### 4.3 Обработчик IRQ1 (INT 09h) — заглушка
Не посылает скан-код, только EOI.

### 4.4 Отсутствует `run_window` в main.rs
Помечен как `todo!()`. GUI версия не работает.

### 4.5 Неполная реализация `0x0F 0x01` (SMSW/LMSW)
SMSW читает CR0, LMSW не реализован.

### 4.6 Нет обработчика INT 08h (таймер) для калибровки PIT
PIT настроен, но таймерные прерывания не эмулируются программно — только через tick_counter.
