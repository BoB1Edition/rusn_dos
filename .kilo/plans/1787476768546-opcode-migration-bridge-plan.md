# План: гибридный мост `dos_core` → `crate/{bus,x86}` и пилотный перенос опкодов

**Дата:** 2026-08-23
**Статус решений:** согласовано с пользователем (мост в `dos_core`; первая партия — уже начатое в `crate/x86`; объём — мост + пилот + рецепт).

## 1. Цель и ограничения

- Перевод проекта с суперобъекта `libs/dos_core` на модульную архитектуру `crate/*` (цель — заменяемый CPU: 6502/JVM/Sega через абстракции `bus`).
- Перенос поштучно: перенесённый опкод **удаляется** из старого кода; неперенесённые **продолжают работать** через старые обработчики.
- Старый бинарник, загрузчики, тесты (`test.sh`) не должны ломаться на каждом шаге.
- Вне объёма этого плана: строковые операции с REP, INT/IRET/DOS-слой, IN/OUT, видео-оптимизации.

## 2. Текущее состояние `crate/*` (анализ)

**Хорошо (используем как есть):**
- `bus::Machine` (память/порты/IRQ), `bus::Cpu::step(&mut dyn Machine)`, `bus::Peripheral` — правильная точка расширяемости.
- `x86::X86Cpu`: цикл префиксов, `fetch_u8/16/32` с автосбором байтов инструкции, `Tracer` (File/Null), `PrefixState`.
- Перенесены: `Registers`, `flags`, `ModRm` (16/32 + SIB, `resolve_address` → физадрес), почти всё семейство MOV, системные (NOP/HLT/INT/IRET/IN/OUT/флаги).
- Есть образец интеграционного теста (`crate/x86/tests/integration_test.rs`) — микропрограмма в памяти + ассерты.

**Дефекты (исправляются в Этапе 0 до любого переноса):**
1. `crate/x86/src/executor.rs` — дубли веток `0x88/0x8A/0x89/0x8B` и `0xB8..=0xBF` (недостижимые паттерны); 32-битные варианты 0x89/0x8B закомментированы.
2. Баг сегментного переопределителя: `cpu.rs:105-110` пишет в `segment_override` байт опкода (0x26/0x2E/...), а `modrm.rs`/`mov.rs` используют его как значение сегмента → неверные адреса. В старом коде хранится **значение сегмента**.
3. `mov_sreg_rm16` — потерян `inhibit_interrupts` при записи в SS (в старом коде есть, `machine.inhibit_interrupts`).
4. Нет REP для строковых; `int` не знает про внутренний диспетчер (маркер `CS == 0xF000`) — поэтому 0xCD/0xCF пока не переносятся.

## 3. Архитектура моста (согласовано)

Зависимости: `dos_core` получает `bus` и `x86` (path-зависимости, без конфликтов версий). Бинарник `src/` не меняется.

- `DosMachine` реализует `bus::Machine`:
  - `read_mem_u8/write_mem_u8` → делегирование в `read_phys_u8/write_phys_u8` (сохраняются A20-маска и перехват видеопамяти 0xA0000–0xC0000 — паритет со старым кодом);
  - `in_port/out_port` — минимальные заглушки с логом (в пилотной партии IN/OUT не переносятся, поведение не меняется);
  - `trigger_irq` — no-op с логом (таймер пока остаётся в старом цикле `run`);
  - `is_halted/halt` → поле `halted`.
- `DosMachine` получает поле `x86_cpu: X86Cpu` (создаётся в `new_with_memory`, `NullTracer`). Источник истины по регистрам/префиксам — поля `DosMachine`, `X86Cpu` — временный носитель на время исполнения одного опкода.
- Таблицы переноса в новом `libs/dos_core/src/bridge.rs`: `MIGRATED_BASE: [bool; 256]` (+ `MIGRATED_0F`, когда понадобится). Перенос строго на уровне опкода: прежде чем ставить флаг, новый исполнитель обязан покрывать **все** варианты опкода (0x66/0x67/сегментный префикс/все формы ModR/M).
- Диспетчеризация в `cpu/run.rs`: перед вызовом старого `execute()`/`execute_0f()` — проверка `bridge::is_migrated(...)` → либо `bridge::run_migrated(machine, opcode)`, либо старая ветка. Сброс префиксов остаётся общим. При пустых таблицах поведение **идентично** текущему.

### Протокол `bridge::run_migrated` (единственное место передачи состояния)

1. Извлечь `X86Cpu` из машины: `std::mem::take(&mut machine.x86_cpu)` (нужен `impl Default for X86Cpu` — NullTracer-заглушка). Заимствование завершается до следующего шага, поэтому далее `machine` можно передать как `&mut dyn Machine`.
2. `cpu.registers = machine.registers.clone()` (~60 байт, дёшево); `cpu.prefixes` заполняется из префиксных полей машины; `segment_override` — **значение сегмента** (как в старом коде).
3. В `cpu.instruction_bytes` записать байты префиксов в формате старого лога (0x66, 0x67, байт сегментного префикса, rep-байт) + байт опкода; `instruction_start_ip = ip - len(записанного)` (в `x86` нужен публичный доступ к `instruction_bytes`/`instruction_start_ip` — добавить аксессоры или сделать поля `pub`).
4. `x86::executor::execute(&mut cpu, machine, opcode)` — `fetch_*` дописывают остальные байты и двигают IP.
5. Возврат: `machine.registers = cpu.registers`; если `cpu.halted` → `machine.halted = true` (аналог `print_error_exit`); машина логирует `log_instruction(csip, &cpu.instruction_bytes)` (формат старого лога сохраняется); `machine.x86_cpu = cpu`.

### Режимы отказа

- Рассинхрон регистров/префиксов между машиной и `X86Cpu` → весь обмен в одной функции-протоколе; покрывается сквозными тестами `test.sh` (программы гарантированно мешают перенесённые и неперенесённые опкоды).
- Неполное покрытие вариантов опкода в новом коде → правило «опкод целиком или не помечен»; `Unsupported` в новом `executor` = баг, ведёт к `halt` как в старом `print_error_exit`.
- Двойное логирование → старый `execute()` для перенесённых опкодов не вызывается, логирует только мост.
- Производительность: `clone()` регистров + `dyn Machine` на инструкцию — приемлемо на этой стадии; зафиксировать как будущую оптимизацию.

## 4. Этапы работ

### Этап 0 — починить `crate/x86` (старый код не трогаем)
- [ ] `executor.rs`: убрать дубли веток; раскомментировать/дописать 32-битные `mov_rm32_r32`/`mov_r32_rm32` (0x89/0x8B с 0x66).
- [ ] `cpu.rs`: `segment_override = Some(значение сегмента)` (0x26→ES, 0x2E→CS, 0x36→SS, 0x3E→DS, 0x64→FS, 0x65→GS); `modrm.rs`/`mov.rs` уже трактуют как значение — проверить.
- [ ] `mov_sreg_rm16`: вернуть `inhibit_interrupts` (добавить поле в `X86Cpu`, мост будет копировать его в машину в Этапе 1).
- [ ] `impl Default for X86Cpu` + аксессоры `instruction_bytes`/`instruction_start_ip` (готовим к Этапу 1).
- [ ] Тесты в `crate/x86/tests`: сегментный переопредель даёт правильный физадрес; MOV reg/mem 16 и 32 бит; существующий тест зелёный.
- Критерий: `cargo check --workspace`, `cargo test --workspace` — зелёные, предупреждений `unreachable pattern` в `x86` больше нет.

### Этап 1 — инфраструктура моста в `dos_core` (нулевое изменение поведения)
- [ ] `libs/dos_core/Cargo.toml`: `bus = { path = "../../crate/bus" }`, `x86 = { path = "../../crate/x86" }`.
- [ ] `machine.rs`: `impl bus::Machine for DosMachine` (раздел 3); поле `x86_cpu: X86Cpu` + инициализация в `new_with_memory`.
- [ ] Новый `src/bridge.rs` + `mod bridge` в `lib.rs`: пустые таблицы, `is_migrated`, `run_migrated` (протокол выше).
- [ ] `cpu/run.rs`: диспетчеризация через `is_migrated`.
- [ ] Обновить `AGENTS.md`: секция про мост и правила переноса.
- Критерий: `cargo check`, `cargo test`, полный `./test.sh` (RUST_LOG=warn) — вывод и поведение **идентичны** базовой линии до моста.

### Этап 2 — пилотная партия опкодов
Состав (всё уже частично есть в `crate/x86`; недостающее дописывается):
1. `0xB0–0xB7` MOV r8,imm8; `0xB8–0xBF` MOV r16/32,imm (+0x66).
2. `0x88/0x8A/0x89/0x8B` MOV r/m↔r (+0x66 для 16/32).
3. `0xA0–0xA3` MOV AL/AX↔[addr] (+0x67/0x66 варианты).
4. `0xC6/C7` MOV r/m,imm (/0; все разрядности).
5. `0x8C/0x8E` MOV r/m↔Sreg (с `inhibit_interrupts` для SS).
6. `0x8D` LEA (16/32).
7. `0x90` NOP; `0xF5/F8/F9/FA/FB/FC/FD` CMC/CLC/STC/CLI/STI/CLD/STD; `0x9E/0x9F` SAHF/LAHF (дописать в `instructions/system.rs`).
8. `0x86/0x87` XCHG r/m↔r; `0x91–0x97` XCHG AX/EAX,rx (новый файл `instructions/exchange.rs` в `x86`).
9. `0x40–0x4F` INC/DEC r16/32 — флаги через `flags::compute_flags_u16/u32`.
10. `0x50–0x5F` PUSH/POP r16/32 — стек физически через `ss<<4 + sp` (как в старом коде, игнорируя сегментные префиксы).

**НЕ переносятся сейчас:** строковые (нет REP), 0xCD/0xCF (нет DOS-диспетчера), 0xE4–E7/EC–EF (порты), 0x8F (групповой, отдельно).

**Рецепт переноса одного опкода (чек-лист, обязателен для всех последующих партий):**
1. Реализовать/дополнить функцию в `crate/x86/src/instructions/*`: сигнатура `fn(&mut X86Cpu, &mut dyn Machine)`; покрыть 0x66/0x67/сегментный префикс/все формы ModR/M; флаги только через `flags::compute_*`.
2. Подключить ветку в `crate/x86/src/executor.rs`.
3. Юнит-тест опкода в `crate/x86/tests` (микропрограмма в памяти → ассерты регистров/памяти/флагов).
4. `bridge.rs`: пометить опкод в таблице.
5. `cargo check --workspace` + `cargo test --workspace`; прогнать `./test.sh` — паритет.
6. **Удалить** старую реализацию: ветку в `libs/dos_core/src/cpu/executor.rs` (или под-диспетчере `cpu/execute/*`) и ставшие мёртвыми функции в `instructions/*`.
7. `cargo check` — компилируется, новых предупреждений `dead_code` нет; повторно `./test.sh`.
8. Только после этого — следующий опкод.

### Этап 3+ (вне этого плана, зафиксировать в `todo.todo`/AGENTS.md)
- REP-цикл в `x86` → перенос строковых + восстановление видео-оптимизаций.
- Внутренний диспетчер прерываний и `handle_intXX` → крейт `dos`; затем 0xCD/0xCF.
- Порты: `Motherboard`-диспетчер (клавиатура 8042, PIC 8259, A20 порт 0x92) → перенос IN/OUT.
- Финал: бинарник работает на `Motherboard + X86Cpu` без `dos_core`; далее замена `X86Cpu` на другие реализации `bus::Cpu`.

## 5. Проверка (каждый этап)

- `cargo check --workspace` — без ошибок и без роста числа предупреждений.
- `cargo test --workspace` — зелёный.
- `RUST_LOG=warn ./test.sh` — полный регрессионный прогон (test1–4, TASM, Biing). После Этапа 1 — сверка с базовой линией до моста; после каждого опкода Этапа 2 — без новых ошибок/падений.
- Первый перенесённый опкод дополнительно сверяет формат лог-файла инструкций (`CS:IP: байты`) с базовой линией.
