# GOALS.md — Цели и векторы развития rusn_dos

## Видение

rusn_dos — **мультисистемный ретро-эмулятор на Rust** с главной целью — **точная эмуляция IBM PC-совместимого DOS-окружения** (80386++, BIOS, VGA/SVGA, DOS API, звук), настолько полная, чтобы без изменений запускать реальные коммерческие DOS-игры и приложения

Конечная цель проекта — **DOS-эмулятор, на котором работает ретро-софт из коробки**: «запустил `GO.COM` — игра поехала».

## Текущие приоритеты разработки

Порядок сверху вниз — ключевой для следующего этапа. Детализация по задачам — в `TODO.md`, найденные ошибки — в `ERRORS.md`.

### P1. Корректность ядра x86 (real mode)

Без точного CPU не запустится ни одна программа. Приоритет:
- Устранение критических UB: RCL/RCR (`1u64 << 64`), SHLD/SHRD (`>> (32 - imm)`), bounds-check `text_buffer`
- Недостающие опкоды: AAA/AAS, BSR/BSF; правильные AF/OF в shift/rotate
- Проверка флагов против эталонных наборов (ficl-pentium / WikiChip) на программных тестах
- Регрессионные тесты на каждый опкод (`crate/x86/tests/`), прогон в CI

### P2. Полнота DOS API (INT 21h)

Программы «прикручиваются» именно к DOS API. Есть база (00h–6Ch: консоль, файлы, MCB, дата/время, country, PSP, SYSVARS, EXEC 4B00h/4Dh, INT 2Fh, INT 33h), не хватает:
- AH=39h/3Ah (MKDIR/RMDIR), AH=59h (extended error), AH=71h (LFN), остатки AH=44h (IOCTL)
- EXEC AL=01h (load-only) и AL=03h (overlay) — пока возвращают CF=1/AX=1
- AH=48h BX=0 (выделение максимального блока) — работает неверно (ERRORS.md #13)
- Проверка соответствия реального поведения (CF/AX/коды ошибок) для каждой функции

### P3. BAT-интерпретатор до уровня COMMAND.COM

Инструменты сборки (TASM/TLINK через `.bat`) и юзер-сценарии требуют полноценного интерпретатора:
- CALL :label (подпрограммы — сейчас не поддержан), FOR, SHIFT, `errorlevel` как переменная
- `set /a`, `set /p`, `choice`
- `bat/runner.rs` уже разбит на подкаталог (`exec.rs`, `commands.rs`, `resolve.rs`, `flow.rs`, `types.rs`, `util.rs`)

### P4. Звук

Конфигурация (`SoundConfig`) уже есть, самого устройства — нет. Это главный «воспринимаемый» дефицит для игр:
- PC Speaker (порт 0x61, прямоугольные импульсы)
- Sound Blaster 16 (DSP, DMA), OPL2/3 (FM)
- Микширование и вывод через CPAL

### P5. VGA/SVGA стабилизация

Рендер и регистры готовы (CRTC/DAC/AC/sequencer, планарные режимы, VBE/LFB), но:
- Проверка пиксельной точности против DOSBox на тест-бенчах (testvga.asm)
- INT 10h AH=0Eh в Mode 13h пишет в лог, а не в видеопамять
- CGA/EGA-совместимость для старых игр

### P6. Стабилизация и качество кода

- Убрать все clippy-предупреждения (десятки), dead code (`init_drivers`, `--mount`), унифицировать типы ошибок (`Box<dyn Error>` vs `String`)
- Тесты в `bus` и `dos` (сейчас 0), навести порядок в `ERRORS.md` по мере фиксов
- EXEC-остатки: не обнуляются Entry-регистры ребёнка и не учитывается `e_maxep` (ERRORS.md #33/#35)
- Исправить CRITICAL/HIGH из ERRORS.md: RCL/RCR и SHLD/SHRD UB (частично устранены: shift.rs на u128; SHLD/SHRD ещё держат `(32-imm)` при imm=0 — проверено 06.11.2026), `inhibit_interrupts`, bounds-check text_buffer

## Векторы развития

### 1. Глубина x86/DOS (главный вектор)
Полное покрытие 80386 real mode, DPMI/защищённый режим в перспективе, DOS API до уровня «стандарта MS-DOS 6.22». Именно на нём проверяется корректность ядра.

### 2. Железо (второй вектор)
PIC/PIT → реальное железо (VGA-тайминги, прерывания), звук (PC Speaker → SB16/OPL), хранение (или INT 13h, образы дискет/HDD, CD-ROM); CD-ROM и IDE открывают дорогу для больших игр, идущих с CD.

### 3. Платформенность (третий вектор)
Остальные крейты (NES, Mega Drive, SNES, Saturn, Dreamcast, JVM) — пока заглушки. Ретро-эмулятор «всё-в-одном» — это долгая цель, каждая новая система — отдельный большой проект. Реальный порядок — приоритет NES (простейший и с большим каталогом), далее Mega Drive.

### 4. Архитектура и качество
Плагинная периферия (`Plugin` trait), feature flags, избавление от god object (в т.ч. `DosSystem`/`runner.rs`), alpha-зрелость модулей по критериям `ALFA.md`. Это инвестиция в то, чтобы эмулятор был поддерживаемым.

## Будущее проекта

**Видение через 2–3 этапа:**

1. **Рабочий DOS-ядро.** Игры из целевого пула запускаются «из коробки» через `.bat`/`.com`, есть звук, стабильные 60 FPS в окне, CLI-режим как замена DOSBox для сборки тестов.
2. **Доступность разработчику**: чистый clippy, тесты на крейты, CI (build+test+lint+интеграционные через test.sh), релизные сборки.
3. **Экосистема**: документация портирования периферии, добавление новой DOS-функции занимает часы, а не дни; система тестовых ROM/DOS-программ.
4. **Мультисистемность**: NES/Mega Drive до состояния «запускается пара-тройка игр», JVM — как символьная площадка.
5. **Долгосрочное**: стабилизация API, альфа-статус для модулей, выпуск v1.0 с набором референсных прогонов и понятным «контрактом» совместимости.

## Этапы

### Этап 1 — «Корректное ядро» (сейчас)

Цель: эмулятор не падает и не валится в UB на целевых программах.

- Зафиксировать текущий прогон `test.sh` — целевой список программ-эталонов
- Устранить CRITICAL-ошибки из ERRORS.md (SHLD/SHRD UB, bounds text_buffer; RCL/RCR уже на u128)
- Добиться чистой `cargo clippy` и отсутствия dead code
- Повысить полноту DOS API: AH=39h/3Ah/59h, EXEC AL=01h/03h, AH=48h BX=0
- BAT: CALL :label, FOR, `errorlevel` как переменная
- Тесты: минимальное покрытие `bus`/`dos`, регрессия x86 в CI
- EXEC: обнуление Entry-регистров ребёнка (#33), учёт e_maxep (#35)

Выход: все программы `test.sh` проходят, clippy чист, ERRORS.md содержит только TODO-пункты без CRITICAL.

### Этап 2 — «Играбельность»

Цель: целевые игры запускаются и проигрываются с звуком.

- PC Speaker + SB16 (DSP) через CPAL
- INT 10h/AH=0Eh в Mode 13h; доводка CRTC/планарной точности по DOSBox
- DOS API «остатки»: IOCTL, LFN, extended error, MKDIR/RMDIR
- Поиск и фикс расхождений на X-COM (geoscape + tactical), Biing! — пофайловый разбор полёта
- Разбиение `DosSystem` на модули (EXEC уже в `process.rs`)

Выход: воспроизводимые сессии в X-COM и Biing! со звуком, воспроизводимые артефакты-скриншоты в тестах.

### Этап 3 — «Железо и платформы»

Цель: расширение системного охвата.

- INT 13h (CHS/LBA), образы дискет/HDD, IDE-контроллер
- Инструменты: отладчик с брейкпоинтами, профиль покрытия опкодов
- NES до состояния «запускается пилотный набор игр» (6502 + PPU + маппер NROM/MMC1)
- Mega Drive — проектация на пилотный набор (68000 + VDP + YM2612)
- CD-ROM/MSCDEX для крупных игровых изданий

Выход: рабочий NES-пилот, запуск игры с HDD/CD в DOS, отладчик встроен.

### Этап 4 — «Стабильность и платформенность»

Цель: v1.0.

- Полное покрытие комментариями (alpha-grade, `cargo doc` на 100%), убрать `todo!()`/`unreachable!()` в целевых крейтах
- Многопоточная модель: анализ и (если целесообразно) перевод видео/аудио/таймера на потоки с сохранением детерминизма
- CI: сборка, lint, unit, интеграционные прогоны, бенчмарки горячих путей
- Релизный цикл: CHANGELOG, семантиеские версии, `--version`, README-гайд по запуску

Выход: v1.0 — DOS-центричный мультисистемный эмулятор с набором референсных прогонов и понятными контрактами.

## Метрики успеха

- **Точность**: 100% целевых программ из `test.sh` + эталонный пул игр проходят без падений и зависаний; расхождение в кадре — только в известных лимитах (звук, тайминги)
- **Качество**: `cargo clippy` без предупреждений, `#![allow(dead_code)]` удалён, `docs/` синхронизированы (проверяется grep-скриптом)
- **Покрытие**: тесты на каждый исправляемый баг (регрессия); доля новых тестов в diff при внесении фич — растёт
- **Процесс**: каждый PR/коммит проходит build+test+clippy; ERRORS.md не содержит пунктов без владельца и версии фикса
